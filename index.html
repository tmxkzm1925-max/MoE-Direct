01 / HOW IT WORKS

MoE의 희소성을,
메모리의 여유로.

큰 모델 전체를 메모리에 두지 않아도 되는 이유

MoE 모델은 매 토큰마다 일부 전문가만 활성화합니다. MoE-Direct는 이 특성을 활용해 전문가 데이터를 NVMe에 두고, 계산에 필요한 시점에 읽어옵니다.

01

가중치는 그대로

재양자화나 라우팅 변경 없이 원본 GGUF의 전문가 데이터를 사용합니다. 기본 packed 경로는 사용 전 원본과 바이트 단위로 검증합니다.

02

읽기 경로를 바꿉니다

전문가 저장 방식, 캐시, 배치, 프리패치를 다룹니다. 서버 시작 시 전문가 전체를 미리 메모리에 적재하지 않습니다.

03

공간과 속도를 선택

기본 packed 경로는 전문가 복사본을 만듭니다. 선택형 virtual 경로는 작은 manifest로 원본을 직접 읽지만, 현재는 packed 경로보다 느립니다.

비교 조건과 출력 검증의 범위 +

약 2.3배라는 수치는 동일한 실행 바이너리와 가중치의 plain mmap 경로를 기준으로 합니다. 다른 런타임 전체보다 빠르다는 주장은 아닙니다.

이 2.3배는 같은 프로그램에서 이 읽기 방식을 끄고 켠 차이이며, 다른 프로그램보다 빠르다는 뜻이 아닙니다.

토큰 일치 검증은 gpt-oss-120b의 greedy decoding, 12쌍의 응답에 한정됩니다. Qwen3.5-122B에서는 실행 간 재현성을 따로 확인했으며, 샘플링 출력이나 Kimi K2.6의 토큰 일치를 주장하지 않습니다.

Qwen3.5-122B의 별도 paired probe는 5.65–6.26 tok/s, arm 평균 5.96 tok/s입니다. 위 표의 릴리스 검증 수치와 합치지 않았습니다. 성능은 NVMe 읽기 처리량과 실행 조건에 따라 달라집니다.

    런타임 준비

  2. 02

    모델 선택

    검증된 GGUF의 모든 분할 파일을 같은 폴더에 준비하고, 런처에서 모델을 선택합니다.

    <drive>:\moe-models\<folder>\Start-MoeDirect.cmd
  3. 03

    리팩 후 연결

    표시되는 디스크 비용과 시간을 확인하고 최초 리팩을 승인합니다. 실행 후 안내된 URL에 OpenAI 호환 클라이언트를 연결합니다.

    클라이언트 연결 안내 ↗

실행 전에 알아둘 점

  • MoE 전용입니다. Dense 모델에는 이 방식의 이점이 없으며, 이미 RAM에 들어가는 모델을 위한 도구도 아닙니다.
  • 기본 packed 경로는 모델 크기의 약 두 배에 해당하는 디스크 공간이 필요합니다. virtual 경로는 원본 외에 작은 manifest와 보고서를 사용합니다.
  • 첫 리팩은 한 번만 수행합니다. 차가운 세션의 첫 대화는 느릴 수 있고, 이후에는 prefix cache를 재사용합니다.
  • 현재 프리뷰는 코드 서명이 없습니다. 체크섬과 안내 문서를 확인하세요. Defender 나 SmartScreen 을 끄도록 요구하지 않습니다.

공개 프리뷰

v0.3 · virtual repack

전문가 복사본 없이 원본 GGUF에서 읽는 선택형 경로를 제공합니다. 현재는 packed 경로보다 느리고, virtual 실행에서도 런처 상태 화면이 packed 경로의 검증 결과(성능 게이트 PASS 표시 포함)를 그대로 보여주는 알려진 한계가 있습니다.

개발 중

v0.3.1 · 구조 정리와 속도 회복

코드 구조와 경계 계약을 정리하고, in-place 경로의 성능 회복과 모델 계열에 적응하는 프리패치를 준비합니다.

후속 목표

엔진 독립화 · 프리필 · 긴 컨텍스트

전문가 실행 코어를 엔진과 분리하고, 프리필 경로 개선은 준비되는 순서대로 내놓습니다. 그 위에서 VRAM·RAM·NVMe에 KV cache를 계층화해, 다음 세대 sparse-attention 모델을 대상으로 같은 소비자 환경에서 100만 토큰 컨텍스트를 목표로 합니다.
